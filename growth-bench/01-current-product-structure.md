# Agentic UG 当前产品结构与前端现状

> 文档状态：现状基线
> 盘点日期：2026-08-17
> 事实依据：当前 `main` 分支源码、根目录架构文档及 `docs/` 内已有方案
> 用途：作为后续前端改版、需求评审、模块取舍和 PRD 编写的共同底稿

## 1. 产品定位

Agentic UG 已经不只是一个投放数据看板，而是由三类能力组成的产品集合：

1. **内部投放数据平台**：供投放团队看收入、消耗、ROI、投手和素材表现。
2. **内部投放作业平台**：供有权限的投手同步账户、管理素材并操作 Facebook 广告。
3. **外部客户门户**：向合创客户展示创作者、产品、素材和投放回报。

仓库里还存在一个独立的“投放协同中心”，承载负责人归属、值班、待办和异常事件。它目前没有并入主站信息架构。

| 产品面         | 入口                                     | 目标用户                 | 核心价值                                     | 当前形态                                        |
| -------------- | ---------------------------------------- | ------------------------ | -------------------------------------------- | ----------------------------------------------- |
| 内部投放平台   | `/` 等主站路由                           | 投放团队、管理者         | 经营看数、投手分析、素材分析、日报、广告操作 | Next.js `Dashboard` 单壳，多面板切换            |

## 3. 用户与权限

### 3.1 内部用户

- 主站通过飞书 OAuth + 卡片确认登录，登录后获得内部看板会话。
- 汇总、个人、素材、日报等查询接口要求内部登录。
- 投放管理页面对已登录用户可见，但广告管理 API 还会校验“投放部门或授权邮箱白名单”。
- 权限控制主要落在 API 层，前端导航尚未按角色隐藏或解释不可用模块。

### 3.2 外部客户

- `/demo` 使用独立账号密码和独立 Cookie，不与内部飞书会话共用。
- 客户门户当前为只读经营看板，不提供创建或修改广告的能力。
- 语言、主题、展示名和头像偏好保存在浏览器本地。

### 3.3 协同中心用户

- `/api/mia` 当前公开、无鉴权。
- 负责人数据来自实时数据库；值班、待办、计划和事故记录主要保存在当前浏览器 `localStorage`。
- 因此它更接近内部原型工具，还不是多人共享的正式协作系统。

## 4. 内部投放平台信息架构

一级导航定义在 `apps/web/src/lib/panels.ts`，当前展示五个面板：

| 一级面板 | 路由            | 用户任务                     | 主要内容                                                                                                | 日期控制                                   |
| -------- | --------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 汇总面板 | `/`             | 判断整体经营表现和异常       | 6 个核心指标、产品明细、渠道明细、当日趋势、缺数补抓                                                    | 使用主站顶栏日期范围                       |
| 个人面板 | `/personal`     | 按投手追踪和调优投放         | 投手 → 产品 → 渠道 → Campaign → AdSet → Ad，多层下钻；修正收入；eLTV；收入来源；AI 建议；预算和状态操作 | 使用主站顶栏日期范围                       |
| 素材面板 | `/creative`     | 筛选和比较素材效果           | Facebook/TikTok 素材排名、3/7/14 天窗口、修正开关、多维筛选、排序、分页、CSV、跨产品复用                | 使用面板内部 3/7/14 天窗口，不使用顶栏日期 |
| 投放日报 | `/daily-report` | 查看单个投手的日级利润表     | 投手选择、汇总/渠道/产品明细 Sheet、月均、合计、CSV                                                     | 使用接口返回的完整可用日期，不使用顶栏日期 |
| 投放管理 | `/ad-manager`   | 管理账户和 Facebook 广告对象 | Token、素材库、Campaign、AdSet、Ad；账户选择；单账户/全量同步；创建和编辑                               | 与日期无关                                 |

### 4.1 汇总面板

核心指标覆盖：

- 雅典娜总收入
- 雅典娜新用户收入
- AF Actual
- AF LTV
- XMP 消耗
- 新用户 ROI

明细层包括产品和渠道两个分析维度。单日模式会补充昨日、上周对比和当日趋势；跨日模式强调区间汇总。页面还能识别雅典娜、AF 或 XMP 缺数，并为 XMP 缺失提供补抓入口。

### 4.2 个人面板

这是当前内部平台信息密度最高、业务动作最多的页面：

- 顶部展示付费、Organic、Restricted 等收入和消耗卡片。
- 主体按“投手 × 产品 × 渠道”组织，并继续下钻 Campaign、AdSet、Ad。
- 支持原始/修正收入切换和 eLTV 口径。
- 支持查看按安装日期归集的收入来源。
- 支持调用 LLM 生成投放建议。
- 支持直接启动/暂停 Campaign、修改 Campaign 或 AdSet 预算。
- 提供原始取数 Skill 下载入口。

它已经同时承担“分析页面”和“操作页面”两种职责。

### 4.3 素材面板

素材面板使用独立的时间窗口，不跟随主站顶栏日期。核心能力包括：

- Facebook 与 TikTok 分表展示。
- 素材名称、负责人、产品、形式、类型、创意、日期等筛选。
- 数值指标筛选和表头排序。
- 修正收入切换。
- CSV 下载。
- 素材命名的跨产品复用。

AIGC 的数据计算和共用组件仍保留在代码中，但 2026-07-17 起前端已移除独立 AIGC 分区，统一归入普通素材方向。

### 4.4 投放日报

日报按投手组织，包含汇总和渠道/产品明细。指标不只覆盖收入、消耗、ROI，还包括投放利润、返点、PWA 成本和推理成本等财务口径。

页面当前有一个结构不一致点：`/daily-report` 没有像其他内部页面一样在服务端入口执行登录跳转，但其 API 仍要求内部登录。

### 4.5 投放管理

投放管理当前聚焦 Facebook，内部二级导航为：

1. Token 管理
2. 素材库
3. 广告系列
4. 广告组
5. 广告

它已经具备账户同步、素材同步、广告对象创建、状态修改和预算修改等真实操作能力。现有架构文档中规划过“创意、审核、策略、审计”等模块，但当前主导航尚未完整实现这些模块。

## 5. 客户门户信息架构

`/demo` 是独立产品面，不复用内部 `Dashboard`。当前侧边栏包含：

| 页面       | 用户任务                 | 核心内容                                                              |
| ---------- | ------------------------ | --------------------------------------------------------------------- |
| 数据看板   | 查看整体合创投放效果     | 曝光、点击、播放、安装、消耗、收入、ROAS、eLTV ROAS、趋势、头部创作者 |
| 创作者     | 比较创作者表现和授权状态 | 排行榜、在投筛选、授权创作者池                                        |
| 产品与档位 | 查看产品和优化档位表现   | 产品 × AEO/VO 矩阵、Campaign 明细                                     |
| 素材表现   | 查看素材投放指标         | 素材/创作者/产品搜索，曝光、点击、播放、CTR、消耗                     |
| 账户设置   | 管理个人展示偏好         | 中英文、深浅主题、展示名、头像                                        |

门户提供全局 7/14/30 天和自定义日期范围。其收入和 eLTV 是面向客户展示的建模口径，包含独立展示系数，不能与内部看板数值直接混用。

## 6. 投放协同中心信息架构

协同中心当前有三个主 Tab：

| Tab      | 核心内容                                                   |
| -------- | ---------------------------------------------------------- |
| 负责人   | App/平台/渠道/负责人筛选，负责人归属卡片，导出和人工备注   |
| 值班台   | 今日值班、重点、待办、计划调整、时间轴、最近更新、产品状态 |
| 异常事件 | 事故列表、事故类型/SOP、严重度、负责人、进展记录、导入导出 |

负责人数据来自实时库；协同记录保存在单机浏览器。该模块如果要正式进入产品，需要先确定鉴权、多人共享存储、操作审计和与主站导航的关系。

## 8. 当前产品结构问题

以下是从现有实现能直接确认的问题，不代表已经确定改法。

### 8.1 一级导航混合了不同性质的任务

“汇总、个人、素材”是分析任务，“日报”是报表任务，“投放管理”是高风险操作任务。目前全部平铺为同级按钮，用户难以建立稳定的产品心智。

### 8.2 全局日期控件并不全局

主站顶栏在五个面板上始终显示日期范围，但只有汇总和个人面板实际消费该状态：

- 素材面板使用自己的 3/7/14 天窗口。
- 日报使用全部可用日期和自身 Sheet 逻辑。
- 投放管理与日期无关。

这会让用户误以为顶栏日期已经过滤当前页面。

### 8.3 分析与操作边界模糊

个人面板已经可以改状态和预算，投放管理也能操作 Campaign/AdSet/Ad。两个页面的职责存在交叉，需要明确：

- 个人面板是否只做“基于数据的快捷调优”。
- 投放管理是否做“完整广告对象管理”。
- 两处操作能力、权限和审计如何保持一致。

### 8.4 权限体验没有完整产品化

投放管理入口对所有内部登录用户展示，但真实权限由 API 再判断。产品层需要决定无权限用户应看到隐藏入口、只读态，还是明确的申请权限页面。

### 8.5 存在失联路由和过期文档

- `/postback` 仍有路由和组件，但已不在导航中，`Dashboard` 也不再渲染该面板；直接访问会进入无对应内容的状态。
- 根文档仍描述独立 `/aigc` 和 Postback 面板，与当前前端实现不一致。
- `panelAccess` 二级解锁接口仍存在，但当前主导航没有对应使用场景。

### 8.6 三套前端体验彼此割裂

内部主站、客户门户和协同中心分别使用不同导航方式、设计令牌、鉴权和状态存储。短期可以作为不同产品面存在，但需要明确品牌一致性和复用边界，避免继续无序分叉。

### 8.7 缺少前端自动化测试

仓库没有可见的页面级测试或端到端测试。后续若调整导航、权限和高风险广告操作，需要同步定义关键流程回归用例。

## 9. 建议的下一版产品分层

以下为讨论建议，不是已确认需求。

### 9.1 内部平台建议分组

```text
经营分析
  - 经营总览
  - 投手分析
  - 素材分析
  - 投放日报

投放执行
  - 广告管理
  - 素材库
  - 自动化策略（规划中）

协同与治理
  - 负责人 / 值班台
  - 异常事件
  - 数据健康 / 回传质量
  - 操作审计（规划中）
```

### 9.2 产品面边界建议

- 内部平台：以日常看数、诊断和执行为中心。
- 客户门户：保持只读、口径透明、面向客户叙事，不暴露内部操作和原始数据细节。
- 协同中心：若继续发展，应并入内部鉴权和数据库，再决定是否进入主站导航。
- API/Postback：作为系统能力和数据治理能力，不应默认与核心业务页面同级展示。

## 10. 下一轮需求梳理需要确认的问题

1. 本轮前端开发的主要对象是内部平台、客户门户，还是两者同时调整？
2. 首要用户是管理者、投手、素材运营、客户还是值班负责人？
3. 本轮目标是重做信息架构，还是在现有导航下新增一个功能？
4. 是否把 `/mia` 的协同能力正式并入内部平台？
5. `/postback`、二级口令和独立 AIGC 页面是恢复、合并还是删除？
6. 投放管理是否只支持 Facebook，还是本轮就要为 TikTok/Google 预留统一交互？
7. 个人面板里的预算/状态操作与投放管理如何分工？
8. 是否建立内部角色体系，并在前端提供只读态、无权限态和申请入口？
9. 是否统一内部主站与客户门户的品牌和设计系统？
10. 本轮成功如何衡量：找数时间、日报制作时间、调预算步骤、异常响应时间，还是客户自助查看率？
