# 广告投放平台架构设计

> 状态：设计阶段
> 分支：`personal/dzh/fb`
> 最后更新：2026-07-27

## 1. 目标

在现有 Sitin 投放数据平台（Agentic-UG-Demo）基础上，新增**自建投放能力**，使投手可以通过平台直接完成广告投放全链路操作，不再依赖 Facebook Ads Manager 等外部工具。

首期支持 Facebook（Meta），架构预留 Google Ads、TikTok 等渠道扩展能力。

## 2. 设计原则

- **渠道抽象**：所有模块以 `channel` 字段区分平台，不写死 `facebook`。通用逻辑只依赖 channel interface，不 import 具体平台实现。
- **读写分离**：广告操作（写）走平台 API 直连，投放数据（读）复用现有 `daily_snapshots` / insights 拉取链路。
- **操作审计**：Facebook API 不区分操作人，平台必须自行记录每一次 CUD 操作。
- **渐进迁移**：现有 Python autopilot / daily-build 脚本能力逐步迁入，不搞一次性重写。

## 4. 模块清单与职责

### 4.1 渠道适配层（P0 — 一切的前提）

**位置**：`packages/fetcher/src/channels/`

这是整个投放平台的底座。所有上层模块不直接调平台 API，而是通过统一的 `ChannelAdapter` 接口。

```typescript
// packages/fetcher/src/channels/types.ts

/** 广告平台通用操作接口，每个平台各自实现 */
interface ChannelAdapter {
  readonly channel: Channel; // 'fb' | 'tt' | 'gg'

  // === Campaign ===
  listCampaigns(accountId: string, params?: ListParams): Promise<Campaign[]>;
  getCampaign(campaignId: string): Promise<Campaign>;
  createCampaign(input: CreateCampaignInput): Promise<Campaign>;
  updateCampaign(campaignId: string, input: UpdateCampaignInput): Promise<Campaign>;
  deleteCampaign(campaignId: string): Promise<void>;

  // === AdGroup (AdSet / AdGroup / AdGroup) ===
  listAdGroups(campaignId: string): Promise<AdGroup[]>;
  getAdGroup(adGroupId: string): Promise<AdGroup>;
  createAdGroup(input: CreateAdGroupInput): Promise<AdGroup>;
  updateAdGroup(adGroupId: string, input: UpdateAdGroupInput): Promise<AdGroup>;

  // === Ad ===
  listAds(adGroupId: string): Promise<Ad[]>;
  getAd(adId: string): Promise<Ad>;
  createAd(input: CreateAdInput): Promise<Ad>;
  updateAd(adId: string, input: UpdateAdInput): Promise<Ad>;
  deleteAd(adId: string): Promise<void>;

  // === Creative ===
  createCreative(input: CreateCreativeInput): Promise<Creative>;
  getCreative(creativeId: string): Promise<Creative>;

  // === Material（上传到平台） ===
  uploadMaterial(input: UploadMaterialInput): Promise<ChannelMaterial>;
  getMaterialStatus(channelMaterialId: string): Promise<MaterialStatus>;

  // === Insights ===
  getInsights(params: InsightsParams): Promise<InsightsResult>;

  // === Pages（用于创意发布 + Partnership Ads） ===
  listAvailablePages(): Promise<AvailablePage[]>;

  // === Account ===
  listAccounts(): Promise<AdAccount[]>;
  getAccount(accountId: string): Promise<AdAccount>;
}

/** 可用 Page（自有 + 合作方授权） */
interface AvailablePage {
  id: string;
  name: string;
  username: string | null;
  picture: string | null;    // 头像 URL，前端做选择器时展示
  category: string | null;   // Page 分类
  source: 'owned' | 'partner'; // FB 不区分，自行根据是否挂载在当前 BM 下判断
  tasks: string[];           // 当前 token 对此 Page 的权限
}
```

**每个平台 adapter 内部封装**：
- HTTP 客户端（URL、请求头、签名/Token 注入）
- Token 生命周期管理（获取、刷新、过期告警）
- 限流处理（退避重试、间隔控制）
- 错误码标准化（各平台错误码 → 统一的 `ChannelError`）

**目录结构**：
```
packages/fetcher/src/channels/
  types.ts              ← ChannelAdapter interface + 通用 DTO
  errors.ts             ← ChannelError 统一错误
  facebook/
    adapter.ts
    client.ts            ← graph.facebook.com HTTP 封装
    token.ts             ← Token 管理：长短期 token、交换、过期预警
    types.ts             ← FB 特有字段类型
  index.ts               ← ChannelAdapterFactory(channel) → 获取实例
```

### 4.2 Token 生命周期管理（P0 — 嵌入在 adapter 内）

不单独作为一个模块，而是 `ChannelAdapter` 实现的一部分：

- **长期 Token 存储**：K8s Secret / `FB_LONG_TOKEN` 环境变量，adapter 初始化时读入
- **过期预警**：token 创建时记录 `expires_at`（长期 token 默认 60 天），距离过期 < 7 天时通过飞书通知提醒管理员去 Graph API Explorer 刷新
- **运行时自动刷新**：每次 API 调用前检查过期时间，短期 token（1-2h）过期自动用 `fb_exchange_token` 换新
- **多账户**：一个 adapter 实例绑定一个 ad account `act_xxx`，不同账户用不同 token 时创建多个实例

### 4.3 权限与广告账户管理（P0）

**位置**：`apps/web/src/lib/dashboard/ad/account.ts` + 前端设置面板

- **投手 ↔ 广告账户绑定**：多对多关系，存库表 `operator_account_binding`
- **权限粒度**：

  | 角色 | 可以做什么 |
  |------|-----------|
  | 管理员 | 查看/操作所有广告账户 + 管理绑定关系 |
  | 投手（读写） | 在自己的绑定账户下建/改/停广告 |
  | 投手（只读） | 只看自己的账户，不能建/改广告 |
  | 观察者 | 只看全平台数据，不能操作 |

- **权限校验**：每个 `/api/ad/*` Route Handler 调用前，从 session 取飞书身份 → 查绑定关系 → 确认有权限操作目标 `act_xxx`

### 4.4 用户认证与飞书登录

**复用现有基础设施**：

- 项目已有飞书 OAuth 登录（`apps/web/src/lib/feishu/`，`fs_user` 表，HMAC cookie）
- 新增强化：登录后关联飞书 open_id → 投手代码（`syh` / `lh` …） → 广告账户权限
- `/api/ad/*` 全部走 `requireApiAuth()` → 校验通过后从 cookie 取投手身份

### 4.5 素材库管理

**位置**：`apps/web/src/lib/dashboard/ad/material.ts`

**设计**：一条素材 = 你们 CDN 上的一个文件。上传到不同平台后各有一条关联记录。

```
materials（通用素材表）
  id          UUID PK
  name        VARCHAR         素材文件名
  file_url    VARCHAR         你们的 CDN 下载地址（https://cdn.xxx.com/materials/video_001.mp4）
  mime_type   VARCHAR         video/mp4, image/jpg
  duration_ms INTEGER         视频时长（毫秒）
  file_size   BIGINT          文件大小（字节）
  app_product VARCHAR         产品（Dora And / Dora iOS ...），可空
  tags        JSONB           自由标签
  created_at  TIMESTAMPTZ
  created_by  VARCHAR         上传人（飞书 open_id）

material_channel_uploads（素材平台上传记录）
  id                    UUID PK
  material_id           UUID FK → materials.id
  channel               VARCHAR       'fb' | 'tt' | 'gg'
  channel_material_id   VARCHAR       平台侧返回的 video_id / image_hash / media_id
  channel_thumbnail_url VARCHAR       平台缩略图地址
  status                VARCHAR       'uploading' | 'ready' | 'failed'
  channel_extra         JSONB         平台特有字段（FB: video_status 详情，TT: 素材审核状态）
  uploaded_at           TIMESTAMPTZ
```

**素材上传流程**：

```
1. 投手上传素材或粘贴 CDN URL → 写 materials 表
2. 选择投放平台、点击「同步到平台」→ 后台读 materials.file_url
   → 调平台 API 上传（FB: POST /{act}/advideos?file_url=xxx）
   → 写 material_channel_uploads，status = 'uploading'
3. 轮询平台转码/审核状态
   → status = 'ready' | 'failed'
4. 建广告时：从 material_channel_uploads 取 channel_material_id
   → 传给 creative 创建接口
```

**FB 素材上传关键点**：

- **视频**：`POST /{act_id}/advideos?file_url=https://cdn.xxx.com/video.mp4`，FB 自己去下载，不需要你们先下载再上传
- **图片**：`POST /{act_id}/adimages?url=https://cdn.xxx.com/thumb.jpg`，返回 `{"images": {"<hash>": {...}}}`，hash 即为图片 key
- **轮询转码**：`GET /{video_id}?fields=status`，等到 `status.video_status == "ready"`
- **创建 creative 时传的是 channel_material_id**（video_id 或 image_hash），**不能直接传 URL**

### 4.6 广告系列管理（Campaign）

**位置**：`apps/web/src/lib/dashboard/ad/campaign.ts`

**通用字段**（存 `ad_campaign` 表）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 内部 ID |
| channel | VARCHAR | 平台标识 |
| channel_account_id | VARCHAR | 平台广告账户 ID（act_xxx） |
| channel_campaign_id | VARCHAR | 平台侧 campaign ID |
| name | VARCHAR | campaign 名称（含投手代号） |
| objective | VARCHAR | 目标类型 |
| status | VARCHAR | active / paused / archived / deleted |
| budget_mode | VARCHAR | cbo / adset_budget |
| budget_amount | INTEGER | 预算（统一存「分」） |
| budget_currency | VARCHAR | 货币 |
| operator_code | VARCHAR | 投手代码（命名解析） |
| app_product | VARCHAR | 产品 |
| channel_extra | JSONB | 平台特有字段（FB: special_ad_categories 等） |

**核心操作**：
- 创建：校验命名规范（必须含投手代号 + 日期）、幂等防重（同日同名已存在则跳过）
- 读取：分页列表 + 筛选（投手 / 产品 / 状态 / channel），跨平台 UNION
- 更新：改状态（ACTIVE ↔ PAUSED）、改预算
- 删除：并非真正删除，status → DELETED / ARCHIVED

**FB 特有**：
- `special_ad_categories` 控制
- CBO 预算在 campaign 层（`POST /{campaign_id}` 改 `daily_budget`，单位「分」）
- `is_adset_budget_sharing_enabled` 必填（v25.0+）

### 4.10 投放数据拉取与处理

**位置**：`services/ad-insight-sync/` + `apps/web/src/lib/dashboard/ad/insight.ts`

**定时拉取**（CronJob `ad-insight-sync`）：

- 每整点拉取 FB Insights 数据
- 字段：`spend, impressions, clicks, ctr, cpc, cpm, actions, action_values, cost_per_action_type`
- 粒度：`level=ad` → 按天聚合
- 落库到 `daily_snapshots`（复用现有表，新增 `kind='fb_insight'` / `kind='gg_insight'` 等）

**与现有数据的联动**：

```
FB Insights (spend, 直连)
  ──JOIN── AF/AD 回传 (revenue, 已有 records_YYYYMM)
  ──JOIN── eLTV 预估 (eltv_cache)
  ──▶ 个人面板 ROI 计算
```

**数据查询**（给看板用）：

- 消耗趋势（按 campaign / adset / ad / 投手 / 产品）
- ROI 计算（eLTV revenue / spend）
- 素材效果排名（按 ad 维度 insights 反查素材）

### 4.11 投放策略/规则引擎

**位置**：`services/ad-autopilot/` + `apps/web/src/lib/dashboard/ad/strategy.ts`

把现有 Python autopilot 的硬编码逻辑抽成**可配置的规则引擎**：

**规则配置示例**（存 `strategy_rules` 表）：

```json
{
  "name": "eLTV ROAS 阶梯调预算",
  "channel": "fb",
  "enabled": true,
  "schedule": "every_hour",
  "conditions": {
    "min_cost": 20,
    "eltv_roas_tiers": [
      {"range": [0, 0.6],   "action": "reduce",  "value": 0.20},
      {"range": [0.6, 0.9], "action": "reduce",  "value": 0.10},
      {"range": [0.9, 1.1], "action": "keep",    "value": 0},
      {"range": [1.1, 1.3], "action": "increase","value": 0.10},
      {"range": [1.3, 1.6], "action": "increase","value": 0.20},
      {"range": [1.6, 2.0], "action": "increase","value": 0.30},
      {"range": [2.0, 999], "action": "increase","value": 0.40}
    ],
    "min_budget": 39,
    "zero_cost_action": "pause"
  }
}
```

**核心规则（从 Python 脚本迁移）**：
1. eLTV ROAS 阶梯调预算/关停
2. 拒审自动换素材（1-2 次灰名单、3 次不再新建、5 次删 ad）
3. 每日定时建广告（AEO + VO 各一条，幂等防重）
4. 降预算失败补偿重试

**策略执行器**：`services/ad-autopilot/` CronJob，按 `schedule` 读规则 → 执行 → 记录结果

### 4.12 审核状态监控

**位置**：`services/ad-review-watch/` + `apps/web/src/lib/dashboard/ad/review.ts`

- 定时轮询所有 ACTIVE campaign 下 ad 的 `effective_status`
- `effective_status == DISAPPROVED` → 解析 `ad_review_feedback` → 写 `ad_review_event` 表

### 4.13 操作审计

**位置**：`apps/web/src/lib/dashboard/ad/audit.ts`

**这是最关键的非功能模块**：Facebook API 不记录操作人，平台必须自行记录。

**表结构**（`ad_operation_log`）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | |
| channel | VARCHAR | 平台 |
| operator | VARCHAR | 投手代码（飞书身份） |
| action | VARCHAR | create_campaign / update_budget / pause_ad / delete_ad ... |
| target_type | VARCHAR | campaign / adset / ad / creative |
| target_id | VARCHAR | 平台侧 ID |
| target_name | VARCHAR | 对象名称（快照） |
| request_params | JSONB | 请求参数（敏感字段脱敏） |
| response | JSONB | 平台 API 返回结果 |
| success | BOOLEAN | 操作是否成功 |
| error_message | VARCHAR | 失败原因 |
| ip_address | VARCHAR | 操作来源 IP |
| created_at | TIMESTAMPTZ | |

**原则**：
- 只增不删不改（append-only）
- 每个 CUD 操作在调平台 API 之前先写日志（`success=false`），API 返回后更新（`success=true` + response）
- 前端操作审计面板：按投手/时间/操作类型/目标 筛选

### 4.14 Partnership Ads 支持

Partnership Ads（合作方广告）在 API 层面与普通广告的创建流程**完全一致**，核心区别仅在于 **creative 使用的 Page 归属不同**：

```
普通广告                    Partnership 广告
─────────────────────      ─────────────────────
creative.page_id =         creative.page_id =
  自有 Page ID               合作方授权的 Page ID
  ↓                          ↓
广告以自有主页名义展示       广告以合作方主页名义展示
```

**API 创建流程没有区别**，`ChannelAdapter` 的 `createCreative` 本身就接受任意 `page_id`，不限制来源。

#### 需要补齐的 3 个点

**① ChannelAdapter 加 `listAvailablePages` 方法**

```
# FB API：查询当前 token 能用的所有 Page
GET /me/accounts?fields=id,name,access_token,username,picture,category,tasks

# 返回的 Page 列表里天然包含两类：
# - 自有 Page（当前 BM 下的）
# - 合作方授权的 Page（对方 BM 管理员在 Page Settings 里授权了该广告账户）
# 两类都混在同一个 data[] 数组里，FB 不做区分
```

FB 原生 API 不标记 Page 来源。自行根据 Page 是否挂载在当前 BM 下来区分 `source: 'owned' | 'partner'`。

**② 创意创建 UI 加 Page 选择器**

创建创意时，`page_id` 从硬编码常量变为下拉选择器，按来源分组展示：

```
┌─────────────────────────────────────────┐
│  选择发布的 Page                         │
│  ┌─────────────────────────────────┐    │
│  │ 🔍 搜索 Page...                  │    │
│  ├─────────────────────────────────┤    │
│  │ 🏢 自有                          │    │
│  │  ○ Dora meet friends            │    │
│  │  ○ Dora: your friend            │    │
│  │  ○ Dora friends center          │    │
│  ├─────────────────────────────────┤    │
│  │ 🤝 合作方                        │    │
│  │  ○ 某KOL的Page                  │    │
│  │  ○ 某媒体的Page                  │    │
│  └─────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

**③ 素材类型扩展：支持推广合作方已有帖子**

Partnership Ads 常见场景是**直接推广合作方已经发布的帖子**（而不新建创意）：

```
POST /{act_id}/ads
  creative = {
    "page_id": "<合作方 Page ID>",
    "object_story_id": "<合作方 Page 的某条 post ID>"   // ← 直接用已有帖子
  }
```

这需要素材概念扩展——素材不仅可以是 CDN 上的文件，也可以是一个**外部帖子**：

```sql
-- ad_material 表补充字段
ALTER TABLE ad_material ADD COLUMN source_type VARCHAR DEFAULT 'file';
-- 'file' = 你们 CDN 上的文件（默认）
-- 'partner_post' = 合作方已发布帖子

ALTER TABLE ad_material ADD COLUMN partner_post_id VARCHAR;
ALTER TABLE ad_material ADD COLUMN partner_page_id VARCHAR;
```

#### 权限前提

- Token 需要 `pages_manage_ads` 权限（你们已有）
- 合作方需要在 Facebook Page Settings 的「Partnership Ads」中将你们的广告账户加入授权列表
- 授权完成后，该 Page 会自动出现在 `/me/accounts` 返回结果中
- **整个过程没有额外的 API 端点需要对接**——Page 授权操作在合作方的 Facebook 网页端完成，API 只是读回结果

#### 与普通广告的关系

| 维度 | 普通广告 | Partnership Ads |
|------|---------|-----------------|
| Campaign 创建 | 相同 | 相同 |
| AdSet / 定向 | 相同 | 相同 |
| 素材上传 | 相同（CDN → FB） | 相同，或直接用合作方帖子 ID |
| 创意创建 | `page_id` = 自有 Page | `page_id` = 合作方 Page |
| Insights 拉取 | 相同 | 相同 |
| 审核 | 由广告主的账户提交 | 由广告主的账户提交（不是合作方） |
| 预算/结算 | 由广告主承担 | 由广告主承担 |

**结论：当前架构完全支持 Partnership Ads，模块设计无需改动，只需要在 3 个点上做补充实现。** 这 3 个点已整合在上方：

- `listAvailablePages` 已在 §4.1 ChannelAdapter 接口中定义
- Page 选择器 UI 将在前端创意管理面板中实现（§5.4）
- 素材类型字段已补充进 `ad_material` 表 DDL（§8）

### 6.2 API 实现模式（与现有接口一致）

```typescript
// apps/web/src/app/api/ad/campaigns/route.ts
import { requireApiAuth } from '@/lib/dashboard/auth';
import { withGuard } from '@/lib/dashboard/guard';
import { listCampaigns, createCampaign } from '@/lib/dashboard/ad/campaign';

export const runtime = 'nodejs';
export const dynamic = 'force-dynamic';

export async function GET(request: Request): Promise<Response> {
  const auth = requireApiAuth(request);
  if (auth instanceof Response) return auth;
  return withGuard(request, auth, async () => {
    const q = new URL(request.url).searchParams;
    // ... 校验参数 + 业务逻辑
    return Response.json(await listCampaigns(auth.operator, q));
  });
}

export async function POST(request: Request): Promise<Response> {
  const auth = requireApiAuth(request);
  if (auth instanceof Response) return auth;
  return withGuard(request, auth, async () => {
    const body = await request.json();
    // ... 校验 + 创建 + 写审计日志
    return Response.json(await createCampaign(auth.operator, body));
  });
}
```
