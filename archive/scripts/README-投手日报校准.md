# 投手日报「修正收入」校准工具

把各投手日报里的产品分表数据，按「新版汇总」的标准公式重算 G:L（修正收入/投放利润/返点/主播成本/运营净利润/总roas），修正投手手填导致的口径偏差与单天错误，并把纯值粘回分表。

## 背景

每个投手有一个飞书日报文档（spreadsheet），里面每个产品×渠道一张分表。分表列结构：

| 列 | 含义 |
|----|------|
| A | 日期 |
| B | 渠道 |
| C | 消耗 |
| D | 男生人数 |
| E | 单价 |
| F | 原始收入 |
| G | 修正收入/总收入 |
| H | 投放利润 |
| I | 返点 |
| J | 主播/PWA成本 |
| K | 运营净利润 |
| L | 总roas |

G:L 本应由统一公式算出，但投手常手填/手改，导致口径不一致或某天算错。本工具用「新版汇总」表里每个产品块的**标准公式**重算 G:L，再把纯数值粘回分表。

## 三个脚本

| 脚本 | 作用 |
|------|------|
| `calibrate-operator-report.js` | **主校准**：读分表 6月 C/D/F → 套标准公式重算 G:L → 粘回分表，输出 K(运营净利润) 差额汇总 |
| `fix-empty-cells-to-zero.js` | 收尾：把 G:L 区间内的「文本空串」单元格改成数字 0（早期 bug 产生的脏数据，汇总公式引用文本会报 #VALUE!） |
| `detect-fix-text-numbers.js` | 收尾：用「乘1法」检测 G:L 里的文本型数字（手填成文本的负数等），转成纯数字 |

## 校准流程（主脚本）

1. 读分表 `A2:L41`，**动态定位 6 月数据段**
2. 提取该段 C/D/F + 原始 K
3. 写入主表「日报核查」(sheet `U7xN0P`) 对应行的 C/D/F
4. 取「新版汇总」(sheet `bqKVkz`) 该产品块的 G:L 公式，retarget 行号后填入日报核查
5. 读回日报核查算出的 G:L 值
6. 把纯数值粘回分表，记录每个产品 K 列新值与原值的差额

## 6月数据段定位规则（重要）

支持四种情况，**起点 = 第一个「6月且日期≤28」的行**（跳过 6/29、6/30 占位行），从起点严格连续递减往下走：

- **整月连续**：6/28 → 6/1，28天
- **起步晚**（月初没投）：如 6/4 才开始投，跑 6/4 → 6/28
- **月末没投只有月初**：如只有 6/1~6/7，跑这一段
- **月内任意孤立连续段**：如只有 6/18~6/21

**自动跳过**两类：
- 无任何 6 月数据（整段是 4/5 月老数据）
- **中间断裂**（缺天/重复，如 6/17 后直接跳 6/14）—— 报警跳过，等补行后单独补跑

> 日报核查表 A 列固定 6/28→6/1。`6/d` 对应核查行 = `2 + (28 - d)`，按段起点算偏移写入，保证公式行号对齐。

## 用法

```bash
export PATH=/home/admin/.npm-global/bin:$PATH

# 批量校准整个文档（推荐）
node calibrate-operator-report.js --doc <spreadsheet_token> --all

# 单个分表
node calibrate-operator-report.js --doc <token> --sheet <sheetId> --product "<新版汇总产品块名>"

# 预演（只验日期对齐，不写入）
node calibrate-operator-report.js --doc <token> --sheet <sheetId> --product "..." --dry-run

# 收尾（可选，按需）
node fix-empty-cells-to-zero.js --doc <token>
node detect-fix-text-numbers.js --doc <token>
```

新增投手时：在 `calibrate-operator-report.js` 顶部加 `XXX_MAP`（sheetId → 新版汇总产品块名，无对应块的设 `null` 跳过），并注册进 `DOC_MAPS`。

## 踩过的坑

- **飞书 cells-get 的 value 字段无法区分文本/数字**（`-$34.10` 文本和数字渲染完全相同）。唯一可靠办法：写 `=单元格*1` 公式，返回 `#VALUE!` 即文本，返回原值即数字（`detect-fix-text-numbers.js` 即此法）。
- **粘回单元格空值一律写数字 0**，绝不写文本空串 `''`，否则下游汇总公式报「文本不能计算」#VALUE!。
- **dry-run 不写日报核查**，读回的是上次残留值，所以 dry-run 的「新值」是假象，只能验日期对齐，看真实数值必须实跑。
- **6/29/6/30 是占位行**，定位起点必须限定 `日期≤28`，否则起点错位、公式行号全乱。
- **retarget 只平移相对引用**（字母直接跟数字），绝不动绝对引用（`F$213` 等）。
- **GraceChat FB 在新版汇总里块名是「GraceChat␣␣FB」（双空格）**，normTitle 去所有空格后能匹配。
- 中间断裂的表（缺天/重复）先不动，等投手补齐行后单独 `--sheet` 补跑。
